# Architecture

- Separate domain/business logic from infrastructure concerns when complexity justifies it.
- Keep domain logic independent from frameworks where practical.
- Use dependency inversion at meaningful architectural boundaries.
- Prefer explicit dependencies over hidden global state.
- Keep API, application, domain, and infrastructure responsibilities distinguishable.
- Do not introduce architectural layers without a concrete reason.
- Use DDD concepts when the domain complexity justifies them.
- Avoid anemic abstractions created only to satisfy a pattern.
