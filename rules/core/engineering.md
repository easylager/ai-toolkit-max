# Engineering

- Prefer simple solutions over unnecessary abstraction.
- Understand existing code before changing it.
- Reuse existing project conventions.
- Keep responsibilities explicit and cohesive.
- Minimize coupling.
- Prefer composition over inheritance where appropriate.
- Avoid premature abstractions.
- Keep public interfaces small and intentional.
- Make failure modes explicit.
- Do not introduce dependencies without a clear benefit.
- Match process depth to task complexity. Do not apply the full planning, estimation, review, or verification workflow to trivial changes. Use deeper analysis when complexity, uncertainty, risk, or blast radius justify it.
