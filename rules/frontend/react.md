# React

- Prefer simple component composition.
- Keep components focused on one responsibility.
- Keep business logic out of presentational components when it becomes complex.
- Prefer local state unless state genuinely needs to be shared.
- Avoid global state by default.
- Keep API/data-fetching concerns separated from UI concerns when complexity justifies it.
- Avoid unnecessary useEffect.
- Prefer derived state over duplicated state.
- Keep effects focused on synchronization with external systems.
- Use accessible semantic HTML.
- Handle loading, error, empty, and success states.
- Avoid unnecessary memoization.
- Reuse existing design system components.
