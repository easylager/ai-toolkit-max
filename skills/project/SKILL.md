# Project

Навигатор проекта. При каждом вызове отвечает на три вещи: **где мы**, **что сейчас главное**, **что дальше** — и делает следующий шаг, если он очевиден и безопасен.

Это не большой skill с режимами. Стадия (`stage` в `.ai/project.md`) сама определяет, какая работа нужна сейчас.

## Правила

- Единственный файл, который этот skill пишет — `.ai/project.md` (`rules/core/project-state.md`). Карточки решений пишет `/decide` в `.ai/decisions.md`. Task-файлы пишут task-level skills. Код не пишется никогда.
- Реконсиляция до действия (`rules/core/common-rules.md`): перечитать `project.md` с диска, обновить статусы узлов из их task-файлов, только потом решать.
- Persist-before-report: сначала записать изменения в `project.md`, перечитать и убедиться, только потом показывать результат.
- Не накапливать. Устаревшее — перезаписывать. Никакой истории, логов и рассуждений в `project.md`.
- Всё, что можно прочитать из task-файла одним чтением, в `project.md` не дублируется.
- Решения о технологиях и архитектуре принимает человек. Этот skill никогда не ставит `ACCEPTED` — он вызывает `/decide` и ждёт выбора.
- Не изобретать стадии и статусы сверх `rules/core/project-state.md`.
- Не делать полный обход репозитория. Если стадии нужно понимание кода — это `/research` внутри узла, не здесь.
- Один вызов — один осмысленный шаг вперёд, а не вся стадия целиком.

## Что делает стадия

| stage | Шаг | Результат в `project.md` |
|---|---|---|
| `DISCOVER` | Понять, что строим. Задать только вопросы, без которых нельзя двигаться. | `Goal`, `Open Questions` |
| `DECIDE` | Найти решения, блокирующие декомпозицию → `/decide` по каждому. | индекс `PDEC-NNN` в `Decisions` |
| `DECOMPOSE` | Разбить на узлы-возможности (поведение, не файлы), проставить зависимости и `READY`/`BLOCKED`. | `Task Graph` |
| `EXECUTE` | Выбрать один `READY`-узел и передать его в task workflow (`/classify` → … → `/verify`). | `status` узла, `task` узла, `Next` |
| `VERIFY` | Собрать уже записанные результаты AC по узлам. Сам ничего не проверяет. | `Progress`, `Blockers` |
| `HARDEN` | Назвать, что осталось учесть перед эксплуатацией. Коротко, без аудита. | `Open Questions`, `Next` |

Стадия продвигается, только когда её результат реально записан в файл.

Нет `.ai/project.md` — создать его: `stage: DISCOVER`, `Goal` из запроса пользователя, пустой граф. Нет запроса и нет файла — сказать об этом и спросить, что строим.

## Human Gates

Стадия остаётся на месте, причина идёт в `Blockers`, `Next` называет, что должен решить человек — когда:

- решение трудно обратить, меняет архитектуру, несёт риск или имеет реальный trade-off (→ `/decide`);
- открытый вопрос делает декомпозицию угадыванием;
- узел ушёл в `REPLAN_REQUIRED` — граф правится, а не обходится.

На очевидные и безопасные шаги разрешения не спрашивать.

## Вывод (на русском)

Всегда одинаковая форма — заголовок стадии, пять вопросов, что дальше. Коротко.

```
DECIDE

Goal:
Внутренний трекер задач для команды из 5 человек.

- [x] Что строим?
- [ ] Как должно работать?   ←
- [ ] Как построим?
- [ ] Как убедимся, что работает?
- [ ] Что дальше?

Нерешённое:
- PDEC-002 хранение сессий — PROPOSED

Дальше: /decide PDEC-002
```

В стадии `EXECUTE` вместо `Нерешённое` — короткая сводка графа:

```
EXECUTE

- [x] Что строим?
- [x] Как должно работать?
- [x] Как построим?
- [ ] Как убедимся, что работает?   ←
- [ ] Что дальше?

Граф: 2 DONE · 1 IN_PROGRESS · 3 READY · 1 BLOCKED

Сейчас: AUTH-01 — пользователь может войти (TASK-003, срез 2/4)

Дальше: /execute TASK-003
```

Блокер показывается одной строкой сразу после стадии и всегда с тем, что нужно от человека. Разделы без содержания не показывать.
